# 标注系统 - 问题排查与解决方案

## 一、遇到的问题

1. **前端无法连接后端** - 浏览器访问前端页面时，显示"无法连接后端服务"
2. **直接访问后端也失败** - 从外部网络无法访问后端API

---

## 二、根本原因分析

### 2.1 前端API地址配置错误

**原始代码** (`frontend/app.js`):
```javascript
apiBase: localStorage.getItem("anno.apiBase") || "http://127.0.0.1:8000"
```

**问题**：`127.0.0.1` 是本地回环地址，当用户从自己的电脑访问服务器时，浏览器会尝试连接**用户自己的电脑**，而不是服务器。

### 2.2 跨域限制

前端和后端运行在不同端口（5173 vs 8000），浏览器默认阻止跨域请求。

### 2.3 进程被挂起

服务启动后状态为 `T`（Stopped），原因是按了 `Ctrl+Z` 或终端关闭导致进程被挂起。

### 2.4 Nginx配置冲突

`default` 配置文件与自定义配置冲突，导致 `/api/` 请求返回404。

### 2.5 云服务器安全组限制

腾讯云安全组默认不放行8000和5173端口，外部网络无法访问。

---

## 三、解决方案

### 3.1 Nginx反向代理（最终采用方案）

**架构**：
```
浏览器 → Nginx(80端口) → /api/xxx → 后端(127.0.0.1:8000)
                    → /xxx → 前端(127.0.0.1:5173)
```

**优点**：
- 统一端口访问，无需跨域
- 只需开放80端口
- 自动推断API地址

**代码修改** (`frontend/app.js`):
```javascript
function apiUrl(path) {
  const base = state.apiBase.replace(/\/$/, "");
  if (!base) {
    return path.startsWith("/") ? path : `/${path}`;
  }
  return `${base}${path}`;
}
```

当 `apiBase` 为空时，使用相对路径（如 `/api/datasets`），Nginx会自动转发到后端。

**Nginx配置** (`nginx.conf`):
```nginx
server {
    listen 80;
    server_name _;
    
    location / {
        proxy_pass http://127.0.0.1:5173;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    location /api/images/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_cache_valid 200 1d;
    }
}
```

## 五、核心知识点

### 5.1 127.0.0.1 vs 0.0.0.0

- `127.0.0.1`：仅本机可访问（localhost）
- `0.0.0.0`：所有网络接口可访问（允许外部访问）

### 5.2 浏览器同源策略

- 不同端口被视为不同源
- 跨域请求需要服务器支持CORS或使用反向代理

### 5.3 Nginx反向代理

- 统一入口，隐藏后端端口
- 解决跨域问题
- 支持负载均衡和缓存

### 5.4 云服务器安全组

- 独立于操作系统防火墙
- 需要在云平台控制台配置
- 默认拒绝所有入站流量

## 六、常见问题速查

### Q1: 进程状态为 T（Stopped）

**原因**：按了 `Ctrl+Z` 或终端关闭

**解决**：
```bash
# 恢复进程
kill -CONT <PID>

# 或重启服务
kill -9 <PID>
nohup python3 -m backend.main --host 127.0.0.1 --port 8000 > backend.log 2>&1 &
```

### Q2: Nginx返回404

**原因**：`default` 配置与自定义配置冲突

**解决**：
```bash
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx
```

### Q3: 外部无法访问但本地可以

**原因**：云服务器安全组未放行端口

**解决**：在腾讯云控制台安全组中添加入站规则，放行TCP:80

### Q4: 访问5173端口无法连接后端

**原因**：5173端口只是静态文件服务器，没有API路由功能

**解决**：使用80端口（Nginx反向代理），或手动配置 `localStorage.setItem("anno.apiBase", "http://服务器IP:8000")`

### 7.4 为什么使用Nginx反向代理

**不使用Nginx时的问题**：
```
浏览器 → http://10.1.0.14:5173
    │
    ▼
前端服务 (5173端口)
    │
    ├── 加载页面 ✓
    │
    └── fetch("/api/datasets")
            │
            ▼
        5173端口没有 /api/ 路由 → 404错误 ❌
```

**使用Nginx后**：
```
浏览器 → http://10.1.0.14 (80端口)
    │
    ▼
Nginx
    │
    ├── 请求 /      → 转发到 5173端口 (前端) ✓
    │
    └── 请求 /api/  → 转发到 8000端口 (后端) ✓
```

### 7.5 端口与IP关系

| 组件 | 监听地址 | 端口 | 访问方式 | 说明 |
|------|----------|------|----------|------|
| Nginx | 0.0.0.0 | 80 | http://服务器IP | 统一入口，对外暴露 |
| 后端 | 127.0.0.1 | 8000 | 仅本机访问 | 由Nginx转发，不对外暴露 |
| 前端 | 127.0.0.1 | 5173 | 仅本机访问 | 由Nginx转发，不对外暴露 |

**为什么后端和前端监听127.0.0.1？**
- 安全：不直接暴露在互联网上
- 统一：所有外部请求都通过Nginx处理
- 灵活：可以更换端口或添加负载均衡而不影响外部访问
